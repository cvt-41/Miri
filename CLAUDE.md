## Releasing a version

1. Bump `<Version>` in `src/Miri.App/Miri.App.csproj` **before** building. The update check compares the release tag with this; if they don't match, people who already have the new version keep getting update prompts.
2. Commit, then `git tag vX.Y.Z` and `git push origin main vX.Y.Z`.
3. Run `installer\build.ps1`, then check `(Get-Item dist\Miri\Miri.App.exe).VersionInfo.ProductVersion`.
4. The user attaches `dist\Miri-Setup.exe` to the GitHub release. **The asset must be named exactly `Miri-Setup.exe`**, because the built-in updater looks for that name.
5. The updater runs the installer with `MIRI_UPDATE=1` (no prompts, keeps Start with Windows and the models). Only installers from v0.3.2 on understand this.

## Problems hit before, and what fixed them

- **Fail-fast crash 0xc0000602 on older Windows 10:** it was .NET's CET shadow-stack compatibility. Fixed with `<CETCompat>false</CETCompat>` in `Miri.App.csproj`. Keep it.
- **Setup.exe "does nothing" when started from Claude's shell:** the IExpress exe exits at once from the sandboxed shell, but works when started normally. Test it with `Start-Process explorer.exe <path>\Miri-Setup.exe`, or extract it (`Miri-Setup.exe /T:<dir> /C /Q`) and run `setup.cmd` directly.
- **YouTube seek slider:** UIA `RangeValue` on YouTube's "Seek slider" is stale and ignores `SetValue`, so use the arrow keys. Skip live streams (title contains 🔴), which jump to the live edge.
- **Weather "Hồ Chí Minh nay":** trailing time words were read as part of the city. The city regex now allows trailing words, and geocoding retries without the last word.
- **Windows location** is turned off at the account level on this PC, and the user doesn't want it changed. Weather uses the city they named (saved to `WeatherCity`).
- **Play-mode hug looked wrong** when it started at her edge. It now triggers only with the cursor at her center (`HugReach`), and she reels the cursor in to her center first.
- **Cheek-pinch lines piled up** in the bubble. `PetController.Says` has a "fresh" flag that clears the bubble (`BubbleWindow.ClearReply`).

## Tooling gotchas in this environment

- **The "Fact-Forcing Gate" hook** blocks the first Edit/Write of each file, the first Bash command, and anything that looks destructive, until you state facts: the files that use this one, the API it affects, data formats, and the user's exact words. State them, then retry. If the first edit to a file in a parallel batch is blocked, every other edit to that file in the batch is blocked too, so resend them all. A Grep (not a Read) that covers the file before the first edit makes the check smoother.
- **Bash heredocs:** never leave a stray `cat > file` with no input in front of a heredoc. It waits on stdin until it times out.
- **Python patches from Bash:** put the script in a file and use raw strings. `\U`, `\b` and similar sequences in normal strings corrupt the C# source.
- **Console encoding:** Python prints Vietnamese through cp1252 and crashes. Set `PYTHONIOENCODING=utf-8`.
- **PowerShell 5.1:** `[ref]$x` needs `$x` to exist first. `Get-ChildItem -Force` trips the destructive-command check, so use `ls -la` in Bash to list folders.
- **graphify:**
  - Use the uv tool's Python from `graphify-out/.graphify_python`.
  - `graphify query` fails (missing `anyio` in that environment), so trace `graph.json` with a short Python script instead.
  - A full rebuild over an older graph trips the shrink guard. Back up `graph.json`, then pass `force=True`.
  - The Obsidian export goes to `C:\Miri Vault\Miri\Graph`, and core-community colours are set in `C:\Miri Vault\Miri\.obsidian\graph.json`.
